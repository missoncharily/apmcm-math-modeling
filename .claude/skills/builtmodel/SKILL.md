# APMCM 数学建模助手

用户可用 `/builtmodel` 调用本技能，例如 `/builtmodel analyze 预测未来销量并优化库存`。仓库内的查询程序提供可重复的分类、检索和模板输出；你负责结合题目上下文解释结果、检查假设并补足推理。

## 执行方式

从仓库根目录运行：

```bash
python .claude/skills/builtmodel/scripts/main.py [命令] [参数]
```

脚本会根据自身位置查找 `papers_database.json` 和 `knowledge_base.json`，无需配置个人目录或硬编码磁盘路径。用户没有指定子命令时执行 `overview`。将用户输入原样传给对应命令；含空格的参数可加引号。

## 命令

- `overview`：显示数据集统计和知识库覆盖范围。
- `analyze <题目描述>`：分类题目并列出匹配方法、适用条件和工具。关键词分类仅作初筛；结合目标、决策变量、约束、数据规模核验结论。
- `method <方法名或问题类型>`：查找方法说明及适用场景，并检查已标注的参考论文。
- `paper <题号或关键词>`：按题号（如 `2025-A`）或关键词搜索论文记录。记录中的 PDF 路径可能依赖本机文件；报告为路径时不要声称已读取 PDF。
- `write <章节>`：给出章节要点；可用的 LaTeX 片段从 `latex_templates.py` 读取。模板中的 `XXX` 均为占位符，必须根据用户数据和实际结果填写。
- `process [阶段]`：输出赛前准备、选题分析、调研建模、求解验证、论文写作或提交检查的阶段任务。
- `code <类型>`：输出可改写的起始代码。先确认输入、变量和目标，再补齐代码并检查依赖、边界条件和结果；不要把模板当成已验证的解答。
- `check [阶段]`：输出结构、数据、模型或终稿检查清单。

## 工作规则

1. 对 `analyze`、`method`、`paper`、`write` 等命令，先运行 CLI 获取仓库数据，再按需阅读 `mathmodel.md`、`APMCM竞赛执行流程总结.md`、`往届题目分析总结.md`、`优秀论文学习指南.md` 中的相关部分。
2. 方法推荐要说明适用条件和局限。数据不足、目标不明或约束缺失时，明确列出待确认信息，不虚构题意、论文内容、模型结果或实验结论。
3. 输出论文内容时贴合用户指定章节，保留符号定义、单位、数据来源和可复核推导；不要把模板占位文本当作事实。
4. 若 CLI 显示论文字段缺少方法或关键词标注，如实说明数据库覆盖不足，并转向题目分析文档，不要把空结果解释为没有相关研究。
